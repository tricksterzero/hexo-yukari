# hexo-yukari

日本語の記事に特化した [Hexo](https://hexo.io/) の関連記事プラグインです。辞書も、人や読者による判定も使わず、記事の本文だけから「ゆかりのある記事」を選びます。

## 特徴

- **辞書を使わずに日本語を語に分ける**: 漢字・カタカナ・英数字の連続を語とみなし、ひらがな(助詞や活用語尾)を捨てます。内容を表す語の多くは漢字かカタカナで書かれる、という日本語の書き方の性質を使います。辞書の版や ICU の単語分割に結果が左右されません。
- **関連の判定に閾値を持たない**: 記事Aの類似度の上位に記事Bが入り、かつ記事Bの上位にも記事Aが入るときだけ「関連あり」とします。調整する値は表示件数だけです。仕組み上、どの記事も表示件数を超えて推薦されないので、一部の記事ばかりが並ぶ偏りが起きません。
- **本文でリンク済みの記事は出さない**: シリーズの一覧など、本文ですでにリンクしている記事は読者の目に入っているので、関連記事の欄には出しません。関連記事が見つからない記事でだけ、リンク済みの記事を予備として出します。
- **新しい記事を先に出す**: 古い記事に着地した読者を、同じ話題の新しい記事へ案内します。
- **キャッシュに左右されない**: 生成のたびに Markdown の本文から計算します。`hexo clean` をしなくても全記事の関連記事が更新されます。

## インストール

npm にはまだ公開していません。ローカルのパスから入れます。

```bash
npm install ../path/to/hexo-yukari
```

[hexo-related-posts](https://github.com/sergeyzwezdin/hexo-related-posts) など、`page.related_posts` を設定する他のプラグインとは同時に使わないでください。

## 設定

サイトの `_config.yml` に書きます。どちらも省略できます。

```yaml
yukari:
  enable: true # false で無効にする
  count: 5     # 表示件数(相互判定で見る上位の件数にも使う)
```

## テーマとの連携

記事のページの `page.related_posts` に、関連記事の `path` の配列を入れます。[NexT](https://theme-next.js.org/) はこの形をそのまま表示できるので、テーマの設定で `related_posts.enable: true` にするだけで使えます。

```njk
{%- for path in page.related_posts %}
  {%- set post = site.posts.findOne({ path: path }) %}
  <a href="{{ url_for(post.path) }}">{{ post.title }}</a>
{%- endfor %}
```

## 仕組み

1. 各記事のタイトルと本文から、コード・タグプラグイン・HTML・URL を取り除きます。
2. 文字の種類の切れ目で語に分けます。3文字以上の漢字の連続は2文字ずつにも分け、`武器使用回数` と `使用回数` のような複合語の部分一致を拾います。1文字の漢字の直後がひらがななら、動詞・形容詞の語幹(`書く`・`良い`)とみなして捨てます。
3. 語ごとに TF-IDF の重みを付け、記事どうしのコサイン類似度を求めます。1記事にしか出ない語は使いません。
4. 相互に上位 `count` 件に入る組を「関連あり」とします。
5. 本文でリンク済みの記事を除き、自分より新しい記事、古い記事の順に、それぞれ類似度の高い順で並べます。関連記事が残らなければ、本文でリンク済みの記事を類似度の高い順に出します。

## 制約

- 数字の直後の漢字(`10回程度` の `回程度` など)は、後ろの語とつながったまま1語になります。
- 略語と正式名(`スラアク` と `スラッシュアックス`)は別の語として扱います。辞書を使わないためです。
- 語の重なりで判定するので、本文が短い記事や、他の記事と語をほとんど共有しない記事では、関連の薄い記事が並ぶか、関連記事なしになります。
- 全記事の組を比べるので、計算量は記事数の2乗に比例します。372記事で約0.2秒でした。
